# Help Me 3.0 — Media, Daily Use & Personal Health

**Date:** 2026-07-25
**Status:** approved, in implementation
**Branch:** `revamp/help-me-2.0`

## Problem

Help Me 2.0 is a complete, offline, bilingual first-aid reference. But it is a *reference*: a user
installs it, reads the disclaimer, and never opens it again until an emergency — which for most
people is never. Two consequences:

1. **Nobody practises.** First-aid knowledge that is only read under panic is not knowledge.
2. **The app has no place in a daily routine**, so it gets uninstalled during the first storage
   cleanup — and is missing on the day it matters.

Separately, the content is **text-only**. Procedures like the recovery position, the Heimlich
manoeuvre, or hand placement for CPR are spatial; prose alone is a poor teacher under stress.

## Goals

- Show **what a procedure looks like**, not only what it reads like — with imagery that carries
  zero copyright risk and does not break the offline guarantee.
- Give the user **reasons to open the app on an ordinary day** — and make each of those reasons
  pay off in an emergency.
- Hold the existing guarantees: **fully offline**, **no account**, **no tracking**, **no ads**,
  **no data leaves the device**.

## Non-goals

- No diagnosis, symptom checker, or triage engine. The app teaches procedures; it does not
  practise medicine.
- No cloud sync, backend, or user accounts. Everything is device-local.
- No in-app video hosting or streaming. Videos are links to already-public content.

## Architecture

The 2.0 principle holds and is extended: **content is data, not screens.** Every addition below is
an immutable data catalogue plus a thin presentation layer, so content can grow without UI work.

```
lib/
├── app/                       # MaterialApp, theme, root scaffold (5 tabs)
├── core/
│   ├── localized_text.dart    # unchanged — ar/en value object
│   ├── media/                 # NEW: image + video value types & credit registry
│   └── widgets/
├── features/
│   ├── conditions/            # + media map keyed by topic id
│   ├── health/                # NEW: medical ID, medicines, first-aid kit
│   ├── learn/                 # NEW: daily tip, lessons, quiz, streak
│   ├── nearby/                # NEW: hospitals / pharmacies / blood banks
│   ├── emergency · home · favorites · settings · about
├── services/
│   ├── notification_service.dart   # NEW: local scheduled notifications
│   └── secure_store.dart           # NEW: encrypted key-value for health data
└── providers/
```

### Navigation

Four tabs become five:

| Tab | Contents |
| --- | --- |
| الرئيسية · Home | search, categories, favorites filter, daily-tip card, quick tools |
| تعلّم · Learn | daily tip, micro-lessons, quiz, streak & badges |
| طوارئ · Emergency | SOS, country numbers, ICE contacts, **nearby** |
| صحتي · Health | medical ID card, medicines, first-aid kit |
| المزيد · More | settings, about, credits, disclaimer |

Favorites loses its tab and becomes a filter on Home — it is one list, not a destination. Settings
and About collapse into "More" to make room without exceeding five tabs.

## Phase 1 — Media layer

### Data model

Media is a **separate catalogue keyed by topic id**, never inlined into the topic constructors.
The topic data files are already ~500 lines each of medical prose; mixing asset paths into them
would make both harder to review, and it must stay possible to add imagery to a condition without
touching a single word of its medical text.

```dart
// core/media/topic_media.dart
class TopicImage {
  final String asset;            // e.g. assets/images/recovery_position.svg
  final LocalizedText caption;
  final String creditId;         // → MediaCredit in the credit registry
}

class TopicVideo {
  final String youtubeId;
  final LocalizedText title;
  final String channel;          // verified via oEmbed at curation time
  final String language;         // 'ar' | 'en'
  final Duration? duration;
}

class TopicMedia {
  final List<TopicImage> images;
  final List<TopicVideo> videos;
}

// features/conditions/data/topic_media_data.dart
const Map<String, TopicMedia> kTopicMedia = {...};
```

`FirstAidTopic` is **not** modified. Lookup is `kTopicMedia[topic.id]`, returning null for topics
with no media yet — so media coverage can be partial and grow over time without breaking anything.

### Image sourcing & licensing

Only two sources are permitted, both free of any attribution-or-else risk:

1. **Wikimedia Commons** files whose license is `Public Domain` or `CC0`, verified through
   `commons.wikimedia.org/w/api.php` (`prop=imageinfo&iiprop=extmetadata`) at curation time — the
   license string is recorded, not assumed. SVG is preferred (small, scales, recolourable).
2. **Original illustrations** authored for this app in the existing category-accent style, for any
   procedure with no clean public-domain source.

Every image is recorded in `assets/images/CREDITS.md` (file, source URL, license, author) and
surfaced in an in-app **Credits** screen. Public-domain and CC0 works require no attribution;
crediting them anyway is honest and costs nothing.

**Excluded on purpose:** photographs of real wounds, blood, or burns. They raise the store age
rating, distress users mid-emergency, and add no instructional value over a clean diagram.

### Video sourcing

Hand-curated only. For each candidate the YouTube **oEmbed** endpoint
(`youtube.com/oembed?url=…&format=json`) is called at curation time to confirm the video exists,
is embeddable, and — critically — that the channel is the one claimed. An ID that fails to resolve
is dropped, never guessed.

Channels: official first-aid and health bodies (Red Cross / Red Crescent, St John Ambulance, WHO,
Ministry-of-Health channels) plus vetted Arabic-language equivalents.

At runtime there is **no API key and no quota**: the thumbnail comes from
`i.ytimg.com/vi/<id>/hqdefault.jpg` and the tap opens YouTube via `url_launcher`. Offline, the
video row degrades to a "needs internet" state; nothing else on the screen is affected.

## Phase 2 — Health (صحتي)

### Medical ID

A card for the user and up to 5 family members: name, blood type, date of birth, allergies,
chronic conditions, current medications, treating doctor, insurance, and free-text notes. Two
presentations:

- **Normal view** — editable.
- **Emergency view** — high-contrast, large type, no navigation, reachable without unlocking the
  card, plus a QR code encoding the same data as plain text so a paramedic can read it from
  another phone without installing anything.

### Medicine cabinet

A list of medicines the household holds: name, form, quantity, expiry date, optional dose schedule.
Two notification kinds: **expiry warning** (30 days before, and on the day) and **dose reminders**
(daily at chosen times).

### First-aid kit checklist

A bundled catalogue of what a home/car kit should contain, grouped by section, each item checkable.
Items with a shelf life (antiseptic, burn gel, adhesive dressings) carry an optional expiry date
that feeds the same reminder machinery as medicines. A completeness ring shows kit readiness.

### Storage & security

Health data is the only genuinely sensitive data this app has ever held. It is stored **only** on
the device, in `flutter_secure_storage` (iOS Keychain / Android EncryptedSharedPreferences), as
JSON under a small number of keys. No analytics, no export-to-cloud, no network path exists for it.
The share action produces a local file or share-sheet payload only when the user explicitly asks.

`shared_preferences` continues to hold non-sensitive settings (theme, language, favorites, streak).

## Phase 3 — Learn (تعلّم)

The engagement engine, and the answer to "why open this on a Tuesday".

- **Daily tip** — one short, actionable first-aid fact per day, selected deterministically from a
  bundled bilingual catalogue by day-of-year so every device shows the same tip without a server.
  Optional daily notification at a user-chosen time.
- **Micro-lessons** — short bilingual lessons, each a handful of cards ending in one check
  question. Sourced from existing topic content, restructured for teaching rather than reference.
- **Quiz** — multiple-choice questions drawn from a bundled bank, scored, with an explanation
  after every answer (including correct ones — the explanation *is* the lesson).
- **Streak & badges** — consecutive-day counter and milestone badges, stored locally. Deliberately
  gentle: no shaming copy, no loss-aversion pressure. This is a first-aid app, not a habit casino.

### Content integrity

Every lesson, question, and tip is bilingual and covered by the same data-integrity tests the 17
topics already have: no empty strings, unique ids, every quiz answer index in range, every
question's correct answer present in its options.

## Phase 4 — Nearby & blood donation

- **Nearby** — hospital, pharmacy, and blood bank searches opened in the device's own maps app via
  the existing `geo:` → Google Maps fallback pattern in `core/maps.dart`, generalised to take a
  query. **No location permission is requested and no location is read or stored** — the maps app
  resolves the user's position itself. This is a deliberate constraint, not a limitation.
- **Blood donation** — record blood type and last donation date; the app counts down the standard
  eligibility interval (90 days) and notifies when the user becomes eligible again.

## Error handling

| Situation | Behaviour |
| --- | --- |
| No internet | Everything except video playback works. Video rows show an offline state. |
| Video removed from YouTube | Thumbnail fails → placeholder; tap still opens YouTube, which shows its own message. |
| Notification permission denied | Features work; scheduling silently no-ops and the UI shows a one-line "enable notifications" prompt. |
| Secure storage unavailable | Health screens show an error state and refuse to write, rather than silently falling back to unencrypted storage. |
| Missing media for a topic | Section is simply absent. Media coverage is optional by design. |
| Maps app absent | Web fallback URL, then a snackbar if that also fails. |

## Testing

Extends the existing 29-test suite, same three layers:

- **Data integrity** — media assets referenced actually exist in `pubspec.yaml` asset dirs; every
  video id is well-formed; every credit id resolves; all new content is bilingual and complete;
  quiz answers valid.
- **Providers** — health profile round-trips through a fake secure store; streak increments on
  consecutive days and resets after a gap; kit completeness maths; expiry-window calculation.
- **Widgets** — health screens render and hide sensitive fields in emergency view; quiz flow
  scores correctly; learn hub renders in RTL; condition detail renders with and without media.

Notification scheduling is tested through an injected fake, never by firing real notifications.

## Privacy policy

`PRIVACY_POLICY.md` must be updated before release. The app still collects nothing and transmits
nothing, but it now *stores* health information locally, and the policy has to say so explicitly:
what is stored, that it is encrypted at rest, that it never leaves the device, that opening a video
is a normal request to YouTube under Google's policy, and how to delete everything (uninstall, or
the in-app "delete my data" action, which Phase 2 must provide).

## Risks

- **Scope.** Four subsystems. Mitigated by phasing: each phase is independently shippable and the
  app is never left broken between them.
- **Medical accuracy of curated video.** Mitigated by restricting to official bodies and verifying
  the channel via oEmbed rather than trusting a search result.
- **Store age rating.** Mitigated by excluding wound photography.
- **App size.** Mitigated by preferring SVG and keeping raster assets few and compressed.
